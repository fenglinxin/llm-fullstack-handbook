01 开篇导语

模型上线后，真实世界的问题来了：流量会波峰波谷、设备千奇百怪、隐私与延迟要求各不相同。

  • 白天 100 QPS，凌晨 2 QPS——买满 GPU 是浪费；
  • 手机端用户要“离线也能用”——7B 模型塞不进去；
  • 有些数据不能出设备——必须本地推理。

解法是三层结构：

  1. 云上 GPU 池：按队列/负载弹性扩缩；
  2. 端侧轻量推理：量化小模型本地跑；
  3. 端云协同：按场景路由（离线/隐私/低时延→端，复杂/最新知识→云）。

本章给容量测算、弹性配置与端云决策的可复现流程。

一句话记住本章：高并发靠“弹性池+队列扩缩”，端侧靠“量化小模型”，端云协同靠“场景路由”；三者合起来叫生产级拓扑。

02 白话原理：弹性与端侧的核心约束

2.1 云上弹性为什么难

LLM 实例的“冷启动”很重：加载 7B 权重+构建 KV 池可能要几十秒到几分钟。所以弹性不是“流量来了再启动”，而是：

  • 基线池（常驻 N 个实例）；
  • 缓冲池（预热好模型、待命）；
  • 突发时把缓冲池转正，同时扩容缓冲。

扩缩指标用队列深度/排队时延，而不是 CPU——LLM 在排队时 CPU 可能并不高。

2.2 端侧为什么难

约束 影响
内存 7B INT4≈4GB，手机吃力
算力 端侧 NPU/GPU 差异大
网络 离线必须本地
隐私 数据不出设备

端侧路线：0.5B–3B 模型 + INT4/INT8（GGUF/MLC/ONNX）+ 专用运行时 + 任务裁剪（只做摘要/分类/短问答）。

2.3 端云协同的决策变量

  1. 数据能否出设备？（隐私/合规）
  2. 是否必须离线？
  3. 时延预算多少？
  4. 知识更新频率？（端侧模型更新成本高）

记忆锚点：云负责“大而全”，端负责“快而私”；路由规则 = 隐私→端、离线→端、复杂/最新→云、简单高频→端。

03 技术选型

3.1 云上集群形态

形态 特点 适合
K8s + 自管 GPU 池 灵活、可定制调度 有运维团队
云托管推理（按实例） 免运维 快速上线
Serverless/按 token 极致弹性 低频/实验

3.2 扩缩策略对比

策略 指标 说明
队列深度 HPA 等待请求数 LLM 首选
GPU 利用率 HPA 算力占用 与队列配合
定时扩缩 业务规律 省缓冲成本
CPU 扩缩 CPU 不推荐（排队时 CPU 不高）

3.3 端侧运行时

运行时 格式 适合
llama.cpp GGUF CPU/各类端
MLC-LLM 编译部署 移动端
ONNX Runtime ONNX 已有 ONNX 生态
厂商 SDK 私有 NPU 专用

3.4 端云协同决策

场景 路由
数据不能出设备 端
必须离线 端
时延 <100ms 端（简单任务）或云（优化后）
复杂推理/最新知识 云
网络差+低风险 端兜底

结论模板：“隐私/离线→端；复杂/最新→云；中间态→先端后云或云+缓存”。

05 分步实操：容量测算与拓扑决策（约 30 分钟）

Step 1 容量测算（10 分钟）

保存 scripts/capacity_plan.py：

# scripts/capacity_plan.py —— 推理实例容量测算
# 用法：python capacity_plan.py <峰值RPS> <单实例req/min(来自batch_sweep)> [目标利用率]
import math
import sys

peak_rps = float(sys.argv[1])
per_min = float(sys.argv[2])
util = float(sys.argv[3]) if len(sys.argv) > 3 else 0.7

per_inst_rps = per_min / 60.0
base = math.ceil(peak_rps / per_inst_rps / util)
buffer = math.ceil(base * 0.5)
print("单实例能力: %.2f req/s" % per_inst_rps)
print("基线实例: %d（利用率目标 %.0f%%）" % (base, util * 100))
print("缓冲实例: %d（预热待命）" % buffer)
print("合计: %d 实例" % (base + buffer))

运行（把第 39 章 batch_sweep 得到的 req/min 填进去）：

python scripts/capacity_plan.py 20 600
python scripts/capacity_plan.py 100 600

容量要按“峰值×1.2 冗余”与“实例冷启动时间”修正；缓冲池大小还取决于扩容需要多久。

Step 2 端云拓扑决策（10 分钟）

保存 scripts/deploy_topology.py：

# scripts/deploy_topology.py —— 端云拓扑决策
# 用法：python deploy_topology.py <privacy:y/n> <offline:y/n> <device_mem_gb> <latency_ms> <know_change:y/n>
import pathlib
import sys

privacy = (sys.argv[1] if len(sys.argv) > 1 else "n").lower() == "y"
offline = (sys.argv[2] if len(sys.argv) > 2 else "n").lower() == "y"
mem_gb = float(sys.argv[3]) if len(sys.argv) > 3 else 4.0
latency_ms = float(sys.argv[4]) if len(sys.argv) > 4 else 300
know_change = (sys.argv[5] if len(sys.argv) > 5 else "y").lower() == "y"

lines = ["# 端云拓扑决策", ""]
if privacy or offline:
    route = "端侧为主（数据不出设备/离线必须）"
    model = "0.5B-3B + INT4（llama.cpp/MLC），复杂任务可选云端兜底（仅限非敏感）"
elif mem_gb < 4:
    route = "云端为主（设备内存放不下可用模型）"
    model = "云上 7B+；端侧仅做唤醒词/意图分类"
elif latency_ms < 150 and not know_change:
    route = "端侧优先（低时延+知识稳定）"
    model = "端侧 1-3B INT4；云侧负责困难样本"
else:
    route = "端云协同（端做简单/隐私，云做复杂/最新）"
    model = "端侧小模型 + 云大模型路由"

lines += ["路由结论: " + route, "模型建议: " + model, "",
          "路由规则示例:", "- 隐私/离线/低时延简单任务 -> 端",
          "- 复杂推理/最新知识 -> 云", "- 网络差且低风险 -> 端兜底", ""]
root = pathlib.Path(__file__).resolve().parent.parent
out = root / "docs" / "deploy_topology.md"
out.write_text("\n".join(lines), encoding="utf-8")
print("\n".join(lines))
print("->", out)

运行两个场景：

python scripts/deploy_topology.py y y 4 100 n    # 医疗本地/离线
python scripts/deploy_topology.py n n 8 500 y    # 通用助手
cat docs/deploy_topology.md

故障/波峰演练：把第 34 章压测叠加到弹性环境，观察扩缩是否跟得上、冷启动期间队列是否爆；记录后归档：

弹性不是“配完就完”：每月用真实流量回放验证一次扩缩曲线与成本。

06 参数详解：生产拓扑速查

参数 参考 说明
基线池 峰值×1.2/单实例能力 常驻
缓冲池 基线 30%–50% 预热待命
HPA 指标 队列深度/排队时延 别用 CPU
端侧模型 0.5B–3B INT4 内存/任务匹配
端云路由 隐私/离线→端 规则可配
冷启动预算 30s–5min 影响缓冲设计

07 高频踩坑排查

坑 1：按 CPU 扩缩 症状：请求全在排队，CPU 不高，HPA 不扩。 解法：用队列深度/排队时延。

坑 2：忽略冷启动 症状：流量突增，新实例还在加载模型，队列已爆。 解法：缓冲池预热；模型加载优化（缓存/快速加载）。

坑 3：spot 实例跑推理 症状：实例被回收，线上断流。 解法：推理用按需+少量 spot 兜底；训练可多用 spot。

坑 4：端侧内存爆 症状：INT4 也放不下或系统被挤爆。 解法：换 0.5–1B、任务裁剪、流式加载、系统内存预留。

坑 5：端云规则一刀切 症状：所有请求上云=隐私风险；全下放=能力不足。 解法：按“隐私/离线/时延/知识变化”分场景路由。

坑 6：端侧模型更新成本被忽略 症状：知识变了要发版更新所有设备。 解法：知识变化快的场景别放端；端侧只放稳定能力。

坑 7：不演练扩缩 症状：第一次大促才发现扩不动。 解法：每月流量回放演练+成本核对。

08 进阶优化：生产拓扑进化方向

① GPU 共享与 MIG：小模型共卡、按需切分，提升 GPU 池利用率。

② 模型多路复用：多 adapter/多模型按请求路由到同一底座，少占显存多接业务（第 14 章）。

③ 按价值路由：简单/低价值请求走端或小模型，高价值走云大模型——成本与体验双优。

④ 端侧增量更新：端侧只更新 adapter/知识增量而非整包，降低发版成本。

⑤ 全球多区域部署：按用户地域就近路由，时延与合规（数据本地化）同时满足。

09 本章核心总结（TOP3）

TOP1：高并发 = 基线池+缓冲池+队列深度 HPA；LLM 冷启动重，弹性必须“预热”而不是“现起”。

TOP2：端侧 = 量化小模型（0.5–3B INT4）+ 合适运行时 + 任务裁剪；先定内存与任务再选模型。

TOP3：端云协同按四变量路由（隐私/离线/时延/知识变化）：隐私离线→端、复杂最新→云；每月做一次扩缩与成本演练。
