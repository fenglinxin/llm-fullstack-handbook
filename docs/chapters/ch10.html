01 开篇导语

前七章我们把通用数据管道建到了“打分”阶段：任何语料进来，都能被清洗、过滤、去重、脱敏并打上质量分。

但通用语料解决的是“会说话”，解决不了“懂行”。你的模型可能很会聊天，却不知道你们公司的打印机型号、报销流程、内部系统的正确叫法——这些知识只存在于你的领域数据里。

本章聚焦主线工程的“领域一跃”：领域专属数据怎么来、怎么变成模型能学的形态。我们会走完三条路：

  1. 内部真实数据：工单、知识库、文档、对话记录（价值最高，合规最严）；
  2. 外部公开语料：行业文档、论文、法规、社区（补充广度，注意版权）；
  3. 合成数据：模板合成 + LLM 生成（解决“量不够”，但必须防幻觉）。

交付物：一个从“领域知识库文档”到“结构化语料 + 合成问答对”的可复现构建流程——它就是主线工程后续 CPT/SFT 的“弹药库”。

一句话记住本章：领域数据构建 = 找对来源（真实为主）+ 转对格式（结构化解析）+ 补足数量（合成为辅）+ 守住真实（专家校验）。

02 白话原理：领域数据到底“补”了什么

2.1 领域模型的三个缺口

缺口 例子 靠什么补
知识缺口 公司打印机型号、内部系统名称 内部文档/知识库
格式缺口 工单格式、报告模板、术语叫法 真实业务样例
行为缺口 “先查知识库再回答”“拒绝编造型号” 规则/对话/指令数据

2.2 领域数据为什么“少而贵”

通用语料按 TB 算，领域语料常常只有几万到几百万条，而且：格式杂（PDF/Word/网页/数据库）、噪声大（OCR 错误、表格错位）、敏感多（客户信息）、更新快（规则三个月一变）。

所以领域数据构建的核心不是“爬得多”，而是把少量高价值数据洗成高质量、可复用、可版本化的资产——前几章的管道在这里全部派上用场。

2.3 领域模型 vs RAG：先想清楚路线

  • 知识会频繁更新 → 优先 RAG（检索增强），数据维护成本低；
  • 需要稳定的格式/行为/推理风格 → 微调/增量预训练；
  • 两者常结合：RAG 喂最新知识，微调教格式与行为。

本章只讲“数据怎么构建”，路线选择（RAG/微调/CPT 怎么配）在第 42 章领域落地时给完整决策树。

03 领域数据三路来源与四类形态

3.1 三路来源

来源 例子 价值 主要成本/风险
内部真实数据 工单、知识库、SOP、客服对话、产品文档 最高（真实格式+真实知识） 合规脱敏、格式杂、量少
外部公开语料 行业白皮书、论文、法规、专业社区、开放数据集 中高（补广度） 版权/授权、领域纯度
合成数据 模板合成问答、LLM 生成指令/推理链 中（补数量/覆盖） 幻觉、同质化、需要校验

真实为主、合成为辅是铁律：合成数据只能补“形态与数量”，补不了“真实业务的最新事实”。

3.2 四类领域数据形态

形态 用途 典型来源
长文档（规则/手册） 增量预训练、RAG 知识源 知识库、产品手册
问答对（QA） SFT、评测 工单沉淀、FAQ
对话/指令 行为与格式微调 客服记录、人工撰写
工具/结构化样本 工具调用、表格理解 API 文档、数据库导出

领域建模的第一步不是写代码，而是画“知识地图”：这个领域有哪些主题、每个主题有什么知识/格式/行为要求、现有数据覆盖了多少——缺什么补什么，而不是有什么用什么。

04 技术选型：解析、合成与质量校验怎么配

4.1 文档解析方案

方案 适合 注意
结构化导出（DB/API/JSON） 内部系统数据 最佳起点，直接拿规范格式
文本抽取（PDF/Word→文本） 文档资料 OCR 错误、页眉页脚噪音（unstructured 类工具可参考）
规则解析（按标题/编号切块） 有固定格式的手册 本章实操采用，零依赖可复现

4.2 合成数据方案

方案 做法 优点 风险
模板合成（本章实操） 规则×问题模板 可控、零幻觉、可复现 句式单一
LLM 改写/扩写 用强模型改写模板问答 多样性高 可能改错事实
LLM 提问生成（QAG） 基于文档生成问题+答案 覆盖广 答案可能脱离原文
推理链/负样本合成 生成思考过程/错误示例 提升推理与拒答 难度高、需专家审

4.3 合成数据防幻觉三件套

  1. 锚定原文：LLM 生成时必须给定原文片段，并强制“只依据原文回答”；
  2. 自动校验：答案关键实体/数值必须在原文中出现（用规则或再次让 LLM 打分）；
  3. 专家抽检：按主题分层抽 10%–20% 人工复核，错误率超标就回炉。

模板合成负责“结构正确”，LLM 合成负责“表达多样”，专家校验负责“事实正确”——三者缺一不可。

Step 2 解析成结构化领域语料（10 分钟）

保存 scripts/build_domain_corpus.py：

# scripts/build_domain_corpus.py —— 按规则编号解析知识库文档 -> domain corpus
import hashlib
import json
import pathlib
import re

root = pathlib.Path(__file__).resolve().parent.parent
src_path = root / "domain" / "domain_sources" / "helpdesk_manual_v2.txt"
out_dir = root / "domain" / "domain_out"
out_dir.mkdir(parents=True, exist_ok=True)

text = src_path.read_text(encoding="utf-8")
records = []
current = None
for raw in text.splitlines():
    line = raw.strip()
    m = re.match(r"^##\s+(R\d+)\s+(.+)$", line)
    if m:
        if current is not None:
            records.append(current)
        current = {"rule_id": m.group(1), "title": m.group(2), "body": []}
    elif current is not None and line:
        current["body"].append(line)

if current is not None:
    records.append(current)

corpus = []
for rec in records:
    body = " ".join(rec["body"])
    body = re.sub(r"^正文[:：]\s*", "", body)
    full_text = rec["title"] + "。" + body
    doc_id = hashlib.sha256(full_text.encode("utf-8")).hexdigest()[:16]
    corpus.append({
        "doc_id": doc_id,
        "rule_id": rec["rule_id"],
        "title": rec["title"],
        "text": full_text,
        "source": "helpdesk_manual_v2",
        "source_version": "v2",
        "tags": ["it_helpdesk"],
        "kind": "rule_doc",
    })

out_path = out_dir / "domain_corpus.jsonl"
with open(out_path, "w", encoding="utf-8") as f:
    for item in corpus:
        f.write(json.dumps(item, ensure_ascii=False) + "\n")
print("rules parsed:", len(corpus), "->", out_path)

运行：

python scripts/build_domain_corpus.py
cat domain/domain_out/domain_corpus.jsonl

产出物：每条规则一条结构化记录（doc_id/rule_id/title/text/source_version/tags）——这就是第 11 章 CPT 语料与后续 RAG 知识源的最小单元。

Step 3 模板合成领域问答对（10 分钟）

保存 scripts/synthesize_domain_qa.py：

# scripts/synthesize_domain_qa.py —— 规则 x 问题模板 -> 合成 SFT 问答对
import json
import pathlib
import random

root = pathlib.Path(__file__).resolve().parent.parent
corpus_path = root / "domain" / "domain_out" / "domain_corpus.jsonl"
out_path = root / "domain" / "domain_out" / "domain_qa.jsonl"

records = [json.loads(line) for line in open(corpus_path, encoding="utf-8")]

templates = [
    "{title}怎么办？",
    "帮我处理一下：{title}",
    "{title}，具体步骤是什么？",
    "按公司规定，{title}应该怎么处理？",
    "遇到{title}，第一步该做什么？",
]

random.seed(2026)  # 固定种子，保证可复现
rows = []
for rec in records:
    answer = rec["text"]
    for tpl in templates:
        question = tpl.format(title=rec["title"])
        rows.append({
            "instruction": "你是公司 IT 帮助台助手，请严格按公司知识库回答，不要编造。",
            "input": question,
            "output": answer,
        })

random.shuffle(rows)
with open(out_path, "w", encoding="utf-8") as f:
    for row in rows:
        f.write(json.dumps(row, ensure_ascii=False) + "\n")
print("synthetic QA:", len(rows), "->", out_path)

06 参数详解：领域数据构建速查

参数 参考取值 说明
领域占比（CPT 混合） 5%–30% 起步 从低到高做消融；过高会伤通用能力（第 11 章展开）
真实:合成比例 建议 ≥1:1，真实优先 合成只补量，不补“事实最新性”
模板数量 每规则 5–20 个 太少句式单一，太多维护成本高
LLM 合成 temperature 0.3–0.7 改写多样性用 0.7，事实生成用 0.3
校验覆盖率 实体 100% + 人工 10%–20% 关键实体自动核对，全文人工抽检
领域词密度 建模用，不硬设阈值 作为领域信号进第 09 章打分
解析容错 解析失败率 <1% 高于 1% 先修解析器，不要手工补数据
评测隔离 领域评测集与训练/合成源严格去重 复用第 07 章 MinHash 对评测集做防污染

07 高频踩坑排查

坑 1：领域数据太少就硬训 症状：只有 200 条领域问答就做 CPT/SFT，模型把 200 条背下来，泛化全无。 解法：先画知识地图，按主题补数据；不够就用模板+LLM 合成扩量，但合成比例别超过真实数据。

坑 2：合成数据“一本正经地胡说” 症状：LLM 生成的问答里出现不存在的型号、流程、政策。 解法：锚定原文生成 + 实体自动校验 + 专家抽检三件套；高危领域（医疗/法律/财务）合成数据必须领域专家逐条审。

坑 3：OCR/格式解析错误直接进训练 症状：PDF 转文本后表格错位、页眉混入正文，模型学到“页眉页脚话术”。 解法：解析后先跑“格式体检”（异常短行率、页眉页脚模式、乱码率），不合格回炉解析器。

坑 4：专家不参与，数据“看起来对” 症状：AI 团队自己判断领域答案对不对，错的知识一路进模型。 解法：每个主题至少一名领域专家参与抽样评审；QA 评审结论进 manifest，作为数据版本的一部分。

坑 5：真实与合成混在一起不分来源 症状：合成数据出问题后，无法定位是哪批数据带偏的。 解法：每条数据带 source/synthetic=true|false/生成器版本；分析与回滚都按来源切分。

坑 6：只建训练集，不建领域评测集 症状：模型训完不知道领域能力到底涨没涨。 解法：从真实业务场景抽 200–500 条做领域评测集（与训练源严格去重），CPT/SFT 前后都跑（第 20 章评估体系）。

坑 7：领域数据“一次建完不再更新” 症状：三个月后业务规则变了，模型还在答旧流程。 解法：知识库版本化 + 增量更新管道：文档变更触发“解析→合成→校验→重新训练/检索库更新”的流程（第 11/44 章衔接）。

08 进阶优化：领域数据构建的进化方向

① LLM 合成 + 自动事实校验流水线：文档切块 → LLM 按原文生成 QA/指令 → 实体与数值自动比对原文 → 不合格自动重试/丢弃 → 专家抽检。把“合成-校验”做成可回放管道，而不是一次性脚本。

② 主动学习回流：线上模型答错/用户纠正的案例，经过脱敏与专家确认后回流领域语料——真实业务是最好的数据矿，但要建立“采集→清洗→评审→入库”闭环。

③ 多领域配比实验：做领域模型前先跑“领域 A:B:通用”配比矩阵小实验（1B 模型上消融），用领域评测分选配比，再放大到目标模型。

④ 合成数据多样化：模板负责骨架、LLM 负责改写、负样本负责拒答边界（“不知道就说不知道”），三类合成按任务需求组合，避免同质化。

⑤ 数据资产化：领域数据按“知识库版本 + 派生数据集 + 评测集”三级管理，每条数据带来源与血缘；当模型效果回退时，能快速定位是知识过期、解析错误还是合成污染。

09 本章核心总结（TOP3）

TOP1：领域数据三路来源——内部真实（最高价值）、外部公开（补广度）、合成数据（补数量）；真实为主、合成为辅，每条数据带来源标签。

TOP2：合成数据防幻觉三件套——锚定原文、实体自动校验、专家抽检；模板合成保结构，LLM 合成增多样，校验决定能不能用。

TOP3：先画领域知识地图再动手：缺什么补什么；训练集与评测集严格隔离；领域数据要版本化、可更新、可回滚——它和模型一样是需要持续运维的资产。
