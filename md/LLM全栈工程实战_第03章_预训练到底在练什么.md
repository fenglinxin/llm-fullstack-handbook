## 01 开篇导语

上一章你亲手微调了一个模型。但你有没有想过一个问题：**你下载的那个“底座”，当年是怎么来的？**

答案可能颠覆很多人的直觉：底座模型不是被人“教”出来的，而是自己玩“文字接龙”玩出来的。

把互联网上几千亿 token 的文本喂给一个巨大的 Transformer，让它反复做同一件事——**看完前面的文字，猜下一个字是什么**——猜错的就调整参数。几万亿次接龙之后，它竟然学会了语法、事实、逻辑，甚至推理。

这个“疯狂接龙”的过程，就叫**预训练（Pre-training）**。

本章不讲公式推导，只回答三个问题：预训练内部到底发生了什么？数据为什么决定模型上限？预训练工程师每天盯的那几个数是什么意思？看完你会发现，后面数据章节（04–13）里的每一个动作，都能在“接龙游戏”里找到理由。

## 02 白话原理：大模型是怎么“接龙”接出来的

### 2.1 一条文本在模型里走四步

任意一段训练文本，在预训练时都会走同样的四步：

**第一步：分词（Tokenization）**
把文本切成小块。中文可能按字或按词元切，英文按子词切。比如“大模型很能打”会被切成若干个 token——切法由 tokenizer 决定，token 是模型眼中的“最小文字单位”。

**第二步：查表（Embedding）**
每个 token 查一张向量表，变成一个向量（比如 4096 维的一串数字）。模型不懂文字，只懂数字；embedding 就是“文字的数字身份证”。

**第三步：Transformer 前向计算**
向量们一层层经过注意力机制和前馈网络。注意力机制负责“看上下文”：预测下一个字时，重点参考前面哪些字。层数越多，能建模的关系越复杂。

**第四步：输出概率并算损失**
最后一层对词表里每一个 token 输出一个概率：下一个字是“很”的概率多少、“能”的概率多少……然后和真实的下一个字对比，算出损失（loss）。loss 越小，说明模型“接龙”越准。

### 2.2 预训练 = 无监督接龙

关键点来了：**预训练不需要人工标注**。文本的下一句、下一个字天然就在文本里——数据自己就是标签。

- 输入：一段文本的前 N 个 token；
- 标签：第 N+1 个 token；
- 损失：模型预测分布与真实 token 的差距（交叉熵）。

所以预训练也叫“自监督学习”。模型在训练时并不知道“1+1=2”是知识，它只知道：**在见过的文本里，看到“1+1=”，下一个出现“=”的概率很高**。大量这样的统计规律叠加，模型就从“背概率”里涌现出了能力。

### 2.3 一个容易误解的点：预训练不是“记忆题库”

模型确实会记住高频文本（比如著名歌词），但真正的能力来自**压缩**：为了把几万亿 token 的接龙都预测好，模型被迫把文字背后的规律压缩进参数里——语法规则、世界知识、推理模式。这也是为什么说“预训练的本质是压缩”，压缩得越好，泛化越强。

> 一句话记住本章：**预训练 = 让模型在超大语料上无限接龙，把语言规律压缩进参数。** 后面所有数据工作，都是为了让这场接龙“接得更干净、更全面”。

## 03 训练架构：一场“工业化接龙”是怎么组织的

玩具接龙一次看一句话，工业预训练一次看**几十万甚至上百万 token**。把规模放大后，训练组织方式有四个关键设计。

### 3.1 数据管线：先处理，再进训练

原始文本不能直接喂给模型，要先走：清洗 → 过滤 → 去重 → 脱敏 → 质量打分 → 配比混合（第 04–10 章逐层展开）。训练侧只接收“已经合格的 token 流”。

### 3.2 样本组装：序列打包（Sequence Packing）

预训练样本不像微调那样一条条独立，而是把清洗后的文档**按固定长度（如 4096 token）切块**，必要时把短文档拼起来填满一个序列，尽量不浪费。切块时要注意：不能从文档中间随意截断造成语义损坏，工业实现通常按段落/文档边界做优雅切分，并记录文档边界供后续去重与溯源。

### 3.3 训练循环：前向 → 算 loss → 反向 → 更新

一次标准迭代（step）是：

~~~text
取一个 global batch（比如 2M token）
  → 前向计算：模型对 batch 内每个位置预测下一个 token
  → 算平均 loss
  → 反向传播算梯度
  → 优化器按学习率更新参数
  → 记录 loss/梯度范数/吞吐，进入下一步
~~~

其中“global batch”由“单卡 batch × 梯度累积 × 并行卡数”放大而来。**预训练看的是 token 总数，不是“条数”**——这是与微调最大的思维差异。

### 3.4 Epoch 数：工业预训练通常不到 1 个 epoch

微调常跑 3–5 个 epoch（数据少、反复看）。预训练语料有数万亿 token，通常**整个语料只过 0.5–1 遍**，重复看数据会加速过拟合与记忆污染。训练中后期会做“数据退火”（把高质量数据占比提高、学习率下降），而不是简单再来一遍。

### 3.5 精度与并行：让“接龙”跑得快

- 精度：主流用 BF16 训练（比 FP32 省一半显存且稳定），大规模会用 FP8 混合精度；
- 并行：单卡装不下就拆——数据并行（每卡一份模型不同数据）、张量并行（一层拆到多卡）、流水线并行（不同层放不同卡）、上下文并行（长序列拆分）等（第 12 章展开）。

## 04 为什么“数据决定模型上限”

### 4.1 三个决定模型效果的因素

模型最终效果由三件事共同决定：**数据质量与配比、模型规模、计算量**。其中数据是“上限”，模型结构是在逼近上限；规模与算力决定你能逼近多少。

### 4.2 数据配比（Data Mixing）为什么重要

真实预训练语料不是一个大杂烩，而是按比例混合：通用网页、代码、数学、书籍、多语种……配比直接影响能力结构：

| 配比倾向 | 模型表现倾向 | 常见代价 |
|---|---|---|
| 网页过多 | 通用对话流畅 | 数学/代码弱 |
| 代码过多 | 代码与逻辑推理强 | 通用闲聊生硬 |
| 书籍/长文过多 | 长文理解好 | 短对话风格偏书面 |
| 领域数据过多 | 领域强 | 通用能力下降（灾难性遗忘的前奏） |

**配比没有标准答案**，要靠小规模对照实验摸索（比如 1B 模型上试配比，再放大到 7B/70B）——这是第 10 章“领域专属数据构建”的核心方法。

### 4.3 Epoch 与数据质量的直觉

- 数据**脏**（噪声、重复、错误）：模型花大量参数去拟合垃圾，能力被稀释；
- 数据**重复**：等于变相缩小语料、放大记忆与过拟合；
- 数据**偏**（只有一种风格）：模型只会那一种风格；
- 数据**少而精**跑多 epoch：小模型可以用，大模型浪费算力。

> 所以预训练团队的第一工程能力，不是调模型，而是**把数据管道做干净、把配比做科学**。这也是本专栏把数据放在训练前面的原因。

## 05 技术选型：不同阶段该用什么框架

预训练框架的选择，本质是“规模”问题。先看梯度：

| 框架/方案 | 适合规模 | 特点 | 适合谁 |
|---|---|---|---|
| 自写 PyTorch 循环 / nanoGPT 类 | 玩具级（<1B、单卡/CPU） | 代码短、逻辑透明，适合理解原理 | 学习、小实验 |
| Hugging Face Transformers + Trainer | 单机小模型（≤3B 量级） | 生态好、上手快，但大规模并行能力有限 | 原型验证 |
| DeepSpeed ZeRO / PyTorch FSDP | 单机多卡到小集群（1B–10B 常见） | 把参数/梯度/优化器状态分片，显存利用率高 | 中小团队主力 |
| Megatron-LM 类（含其并行策略被多框架复用） | 10B 以上、多节点 | 张量/流水线/上下文并行成熟，工业预训练主流血统 | 大模型团队 |
| 云厂商训练平台 | 任意规模 | 集群、调度、断点续训托管 | 不想自建集群的团队 |

选型结论三句话：

1. **学原理用最小框架**：nanoGPT/自写循环，几百行代码就能看到完整训练循环；
2. **中小规模用 DeepSpeed/FSDP**：单机 8 卡跑 7B–13B 预训练/增量预训练的主流选择；
3. **大规模预训练交给成熟框架或云平台**：不要从零造分布式轮子，那是大厂都不愿重复的工作。

> 提醒：预训练框架选型不等于“越强越好”。你的瓶颈如果是数据，换 Megatron 不会让 loss 降得更快；**先解决数据，再升级框架**。

## 06 核心参数与指标：预训练工程师的“仪表盘”

### 6.1 核心参数速查

| 参数 | 大白话 | 常见参考区间 | 说明 |
|---|---|---|---|
| 全局 batch（token 数） | 一次更新看多少 token | 小模型 0.5M–2M；大模型 4M–60M 甚至更高 | 太大会不稳定，太小效率低，需配合 LR 调整 |
| 序列长度 | 一次看多长的上下文 | 4096–131072（视模型设计） | 越长越贵，与训练效率、应用场景匹配 |
| 峰值学习率 | 参数更新的最大步长 | 3e-4~3e-3（随模型变大下降） | 大模型通常用更小 LR |
| 学习率预热/退火 | 先升后降 | warmup 数百到数千步；末期退火 | 稳定起步、收尾精修 |
| 精度 | 训练数值格式 | BF16 主流，FP8 前沿 | 精度错误会表现为 loss spike |
| epoch | 语料过几遍 | 大语料通常 <1 | 重复数据要格外警惕 |

> 这些区间只是“参考坐标系”，真实取值由模型规模、数据量、硬件共同决定，务必以自己小规模实验为准（第 12 章详解超参选型）。

### 6.2 训练日志里的五个数

| 指标 | 看什么 | 正常信号 | 危险信号 |
|---|---|---|---|
| train loss | 拟合程度 | 平稳下降 | 不降、突然跳高（spike） |
| val loss | 泛化程度 | 与 train loss 同步下降 | 与 train loss 拉开差距=过拟合 |
| grad norm | 梯度健康度 | 稳定在个位数量级 | 突然暴涨=梯度爆炸；长期趋近 0=梯度消失 |
| tokens/s 或 samples/s | 训练速度 | 稳定、可预测 | 忽高忽低=IO/网络/掉卡 |
| MFU | 算力利用率 | 越高越好（成熟集群 40%–60% 已属优秀量级，随硬件与模型浮动） | 长期个位数=大概率在空转 |

**本章先记住一件事：看训练日志不是只看 loss，而是“loss + val loss + grad norm + 吞吐”四件套一起看。** 第 13 章会给完整日志案例与排查手册。

## 07 分步实操：5 分钟亲眼观察一次“loss 下降”

理论讲完必须动手。这里用一个**迷你预训练实验**让你亲眼看到：同样的训练循环、同样的 loss 曲线，正是大模型预训练的缩小版。

前置条件：沿用第 02 章的 llm-demo 工程（有 data/demo_helpdesk.jsonl，装了 torch 与 transformers）。

### Step 1 保存脚本 scripts/mini_pretrain.py

~~~python
# scripts/mini_pretrain.py —— 迷你预训练：观察 next-token 接龙与 loss 下降
import json
import torch
from transformers import GPT2Config, GPT2LMHeadModel

# 1. 用第 02 章帮助台问答拼一个小语料（仅做教学演示）
corpus = []
with open("data/demo_helpdesk.jsonl", encoding="utf-8") as f:
    for line in f:
        obj = json.loads(line)
        corpus.append(obj["input"])
        corpus.append(obj["output"])
text = "\n".join(corpus)
print("corpus chars:", len(text))

# 2. 字符级分词：把每个字符映射成数字
chars = sorted(set(text))
stoi = {ch: i for i, ch in enumerate(chars)}
ids = [stoi[ch] for ch in text]

# 3. 切成 128 token 的序列块（训练样本）
SEQ = 128
chunks = []
for i in range(0, max(1, len(ids) - SEQ), SEQ // 2):
    chunk = ids[i:i + SEQ]
    if len(chunk) == SEQ:
        chunks.append(chunk)
print("chunks:", len(chunks), "vocab:", len(chars))

# 4. 定义一个小 GPT：2 层、2 头、64 维（几秒就能跑一步）
cfg = GPT2Config(
    vocab_size=len(chars),
    n_positions=SEQ,
    n_ctx=SEQ,
    n_embd=64,
    n_layer=2,
    n_head=2,
)
model = GPT2LMHeadModel(cfg)
opt = torch.optim.AdamW(model.parameters(), lr=1e-3)

# 5. 训练循环：前向 -> loss -> 反向 -> 更新（工业预训练就是把它放大几万亿倍）
for step in range(200):
    xb = torch.tensor(chunks[step % len(chunks)]).unsqueeze(0)
    loss = model(input_ids=xb, labels=xb).loss
    opt.zero_grad()
    loss.backward()
    opt.step()
    if step % 10 == 0 or step == 199:
        print("step %4d  loss %.4f" % (step, loss.item()))
~~~

### Step 2 运行并记录

~~~bash
cd llm-demo
python scripts/mini_pretrain.py
~~~

预期输出长这样（数值因随机种子而异，但趋势相同）：

~~~text
corpus chars: 12345
chunks: 190  vocab: 87
step    0  loss 4.4621
step   10  loss 3.8120
step   20  loss 3.3011
...
step  190  loss 1.2304
step  199  loss 1.1587
~~~

### Step 3 观察三个现象（这就是本章要建立的直觉）

1. **loss 从 4 点多一路降到 1 点多**——模型在“学会接龙”：初始时每个字符概率接近均匀，所以 loss≈log(词表大小)；下降说明预测越来越准。
2. **下降先快后慢**——容易学的规律（标点、常用词）先学会，难学的规律后学会，这就是预训练曲线的常见形状。
3. **同一个语料反复看（这里 200 步相当于看了多遍）**——loss 还能继续降，但这是“背数据”而非“学规律”；真实预训练语料巨大，通常不过 1 个 epoch，正是为了避免这种假收敛。

> 实验说明：这个迷你模型只有约 30 万参数，训练的是 120 条问答拼接的小语料，**不是工业预训练**。但它完整复刻了工业预训练的核心循环——数据切块、前向、交叉熵 loss、反向、更新。把语料换成几万亿 token、把模型换成几千亿参数、把单卡换成集群，就是 GPT 级别的预训练。

## 08 高频踩坑：新手理解预训练最常见的五个误区

**误区 1：把预训练当成“多跑几个 epoch 的微调”**
症状：小语料反复过几十遍，loss 很低，以为模型变强了。
真相：预训练语料大、通常不到 1 epoch；重复数据只会带来记忆与过拟合。判断标准不是 train loss，而是 val loss 与下游评测。
解法：区分“微调（小数据多 epoch）”和“预训练（大数据少 epoch）”两套思维，别混用。

**误区 2：只看 train loss，不看 val loss 和 grad norm**
症状：训练日志只盯 loss，loss 降了就以为一切正常。
真相：过拟合、梯度爆炸、数据泄漏都不会第一时间反映在 train loss 上。
解法：把“loss + val loss + grad norm + 吞吐”四件套做成固定监控（第 13 章给完整模板）。

**误区 3：数据配比“拍脑袋”，不做对照实验**
症状：通用语料和代码按 9:1 混，理由是“别人都这么配”。
真相：配比必须服务于目标能力，且随数据质量变化。
解法：先用小模型做配比消融（固定算力预算，对比 2–3 组配比的评测分），再放大。

**误区 4：精度设置不当，loss 突然跳高**
症状：训练几千步后 loss spike，或一开始就不收敛。
真相：可能是 FP16 溢出、BF16 与硬件不匹配、梯度裁剪缺失。
解法：主流直接 BF16；换精度后先小规模跑通再放大，任何精度改动都要重测稳定步数（第 12/13 章展开）。

**误区 5：loss 低 = 模型强**
症状：拿 train loss 到处说“我们模型收敛得很好”。
真相：预训练的 loss 与下游能力不是线性关系，代码/数学等能力要靠专门评测集验证。
解法：预训练期间就要周期跑“轻量评测集”（HellaSwag/MMLU 等公共基准或自建领域集），把 loss 与能力两条曲线一起看（第 20 章评估体系）。

## 09 进阶优化：从“看懂原理”到“能做预训练工程”

**① 用“小模型试点”代替拍脑袋**：任何配比、超参、数据策略，先在一两个 1B 级模型上做短周期实验（固定 token 预算），用评测分排序，再放大到目标规模。这是预训练团队最核心的工作方法。

**② 建立“预期 loss”曲线**：用公开 scaling law 经验或自家小规模数据拟合“数据量→loss”的预期曲线，训练实际 loss 明显偏离预期时，优先怀疑数据问题而非模型问题——这是高级团队排查训练异常的常用手段（第 13 章展开）。

**③ 盯 MFU 与数据加载**：MFU 低时先查数据加载、通信与 kernel 是否瓶颈，再决定加机器；加机器不解决数据瓶颈，只会更亏钱。

**④ 不要轻易启动全量预训练**：对绝大多数团队，正确答案是“开源底座 + 领域数据增量预训练（第 11 章）+ SFT/对齐”。全量预训练适合数据、算力、评测、工程四件事都齐的团队。

## 10 本章核心总结（TOP3）

**TOP1**：预训练的本质是“无监督文字接龙”——文本自己提供标签，模型通过预测下一个 token 把语言规律压缩进参数；分词、embedding、Transformer、交叉熵四步构成了训练的最小循环。

**TOP2**：数据决定模型上限：配比决定能力结构，脏/重/偏的数据会直接稀释能力；工业预训练语料巨大通常不到 1 个 epoch，而微调才是小数据多 epoch 的玩法，两套思维不能混。

**TOP3**：预训练工程师的仪表盘是“loss + val loss + grad norm + 吞吐（MFU）”四件套，只看 train loss 等于盲飞；所有判断最终要靠评测集，而不是 loss 数字本身。
