## 01 开篇导语

大模型生成慢的根因很反直觉：**每一步只生成一个 token，但整张卡要为这一个 token 跑一遍**——瓶颈是显存带宽，不是算力。就像一辆卡车只运一件小包裹。

投机解码（Speculative Decoding）的思路是“拼车”：让一个便宜的小模型（草稿）先快速猜 k 个 token，大模型（目标）一次前向**同时验证这 k 个猜测**——猜对的直接收下，猜错的按概率修正。分布与原始模型一致，但每轮“运输”的 token 变多了。

收益能不能兑现，取决于三件事：

1. **接受率**：草稿猜中的比例（通常 0.5–0.85）；
2. **草稿成本**：草稿每步要便宜（如 5–10 倍）；
3. **投机长度 k**：一次猜几个（常见 4–8）。

本章讲清原理、给出收益模拟器，并带你用 vLLM 做开/关实测。

> 一句话记住本章：**投机解码 = 用“便宜的草稿多猜 + 昂贵的目标一次验证”把 decode 从逐 token 变成逐段；收益看接受率与草稿成本，必须实测。**

## 02 白话原理：先猜后验

### 2.1 普通 decode 的浪费

~~~text
第 1 步：目标模型生成 token A
第 2 步：目标模型生成 token B   （每步都全量前向）
第 3 步：……
~~~

每一步都在搬运整模型权重，却只产出 1 个 token。

### 2.2 投机 decode 的流程

~~~text
① 草稿模型（小、快）快速猜 k 个 token：[A', B', C', D']
② 目标模型（大、慢）一次前向，同时算出这 4 个位置的分布
③ 逐个校验：A' 概率够高→接受；不够→按拒绝采样修正
④ 接受的前缀直接作为输出，再进入下一轮
~~~

关键保证：**拒绝采样让输出分布与原模型一致**（不是简单“信草稿”）。

> 记忆锚点：**草稿负责“广撒网”，目标负责“一锤定音”；撒网便宜、定音权威，配合起来每轮多收几个 token。**

## 03 投机解码家族与选型

| 方案 | 草稿来源 | 特点 | 适合 |
|---|---|---|---|
| 小模型投机 | 同 tokenizer 的小模型 | 实现简单、框架支持好 | 通用首选 |
| 自投机（self-speculative） | 目标模型跳层/提前退出 | 不用额外模型 | 有现成同族模型 |
| Medusa | 目标模型加多个解码头 | 无草稿模型、接受率可观 | 追求收益 |
| EAGLE | 基于特征草稿 | 接受率高 | 进阶玩家 |
| n-gram/检索草稿 | 历史/语料 n-gram | 零训练 | 重复性文本场景 |

**什么时候值得开**：

| 场景 | 收益 |
|---|---|
| 低并发、长输出 | 大（decode 带宽瓶颈） |
| 高并发已打满算力 | 小/无（GPU 已忙） |
| 短输出（<20 token） | 小（投机开销占比高） |
| 采样/贪婪都支持 | 贪婪更简单 |

> 工程结论：**先试“同 tokenizer 小模型投机”（框架原生支持），收益不达标再上 Medusa/EAGLE 类；高并发饱和场景别指望投机。**

## 05 分步实操：收益模拟与框架实测（约 1 小时）

### Step 1 收益模拟器（10 分钟）

保存 scripts/spec_sim.py：

~~~python
# scripts/spec_sim.py —— 投机解码收益粗估
# 用法：python spec_sim.py <投机长度k> <草稿成本比r>
import sys

k = int(sys.argv[1]) if len(sys.argv) > 1 else 4
r = float(sys.argv[2]) if len(sys.argv) > 2 else 0.1

def expected_tokens(p):
    # 每轮期望接受数（至少产出 1 个修正 token）
    e = p * (1 - p ** k) / (1 - p) if p < 1 else k
    return max(1.0, e)

print("投机长度 k=%d，草稿单步成本=目标单步的 %.0f%%" % (k, r * 100))
print("p(接受率) | 每轮期望 token | 相对加速(粗估)")
for p in (0.5, 0.6, 0.7, 0.8, 0.9):
    e = expected_tokens(p)
    speedup = e / (r * k + 1.0)
    print("%.1f      | %.2f           | %.2fx" % (p, e, speedup))
~~~

运行：

~~~bash
python scripts/spec_sim.py 4 0.1
python scripts/spec_sim.py 6 0.15
~~~

> 模拟器是“理想化粗估”：实际还要算验证开销、批处理效应与草稿模型加载显存。结论方向比数字更重要：**接受率 0.5→0.8 的收益差距远大于 k 4→6。**

### Step 2 准备草稿模型并起服务（10 分钟）

选择与目标同 tokenizer 的小模型（如 Qwen2.5-1.5B-Instruct 给 7B 当草稿；也可复用第 22 章 3B 学生）。vLLM 启动投机解码（参数名以版本 --help 为准）：

~~~bash
# 关闭投机（基线）

# 开启投机（8001；示例为旧/新参数形态之一）
vllm serve models/helpdesk-sft-merged --served-model-name helpdesk-spec --port 8001 --max-model-len 4096 \
  --speculative-config '{"model": "models/Qwen2.5-1.5B-Instruct", "num_speculative_tokens": 4}'
~~~

> 若你的 vLLM 版本不支持该参数形态，以官方 speculative decoding 文档为准；草稿与目标必须共享 tokenizer。

## 07 高频踩坑排查

**坑 1：草稿模型太大**
症状：草稿成本吃掉验证收益。
解法：草稿用 1/4~1/10 规模；模拟器先估 r。

**坑 2：高并发下期待收益**
症状：并发 32 时开关几乎无差。
解法：投机利好 decode 带宽瓶颈场景；高并发已是 compute-bound。

**坑 3：短输出开投机**
症状：输出 10 个 token，投机开销占比高。
解法：输出 >50 token 再启用；短请求走普通路径。

**坑 4：采样分布被破坏**
症状：实现错误导致输出分布与原模型不一致。
解法：用框架成熟实现；验证贪婪一致性+分布统计。

**坑 5：tokenizer 不一致**
症状：草稿与目标词表不同，投机失效或报错。
解法：同 tokenizer 家族；换模型重验。

**坑 6：只信模拟器**
症状：模拟 2x，实测 1.1x。
解法：实测为准；记录并发、输出长度与草稿成本。

**坑 7：显存没预算**
症状：草稿模型把 KV/批处理显存挤爆。
解法：先算显存账；小卡可考虑自投机/无额外模型方案。

## 08 进阶优化：投机解码进化方向

**① Medusa/EAGLE**：在目标模型上加解码头/特征草稿，无独立草稿模型且接受率更高——收益不足时的下一步。

**② 自投机**：用目标模型的浅层/跳层输出当草稿，省掉额外模型显存，代价是实现复杂度。

**③ n-gram 草稿**：对模板化/重复文本（日志、代码补全）零训练高命中。

**④ 投机+PD 分离**：prefill 阶段无投机必要，decode 阶段配合 PD 分离单独优化（第 39 章）。

**⑤ 动态开关**：按实时并发/输出长度/草稿接受率自动开关投机，让收益最大化。

## 09 本章核心总结（TOP3）

**TOP1**：投机解码 = 草稿多猜 + 目标一次验证 + 拒绝采样保分布；decode 的带宽瓶颈让它“一次前向多收 token”。

**TOP2**：收益三要素是接受率、草稿成本、投机长度 k：先模拟再实测；低并发长输出开、高并发饱和关。

**TOP3**：框架成熟实现优先（vLLM/SGLang/TRT-LLM），草稿须同 tokenizer；上线前做贪婪一致性与 20 题质量回归。
