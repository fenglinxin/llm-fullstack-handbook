## 01 开篇导语

主线 46 章讲的是“工程”：数据、训练、部署、优化。但工程里大量决策的根源在**模型结构**：

- 为什么 Transformer 推理要 KV Cache，而 Mamba 只需要一个固定状态？
- 为什么 MoE 参数量大却比同规模稠密模型省算力？
- 为什么长音频、长视频不能直接塞进普通 Transformer？
- 为什么 CNN 时代没人讨论“上下文窗口”？

这些问题的答案都在模型结构里。本篇作为第 00 章，把全网主流架构做一次**通俗拆解 + 工程落地对比**：循环网络、Transformer、Mamba/SSM、MoE、稀疏注意力、世界模型、音频模型、视觉与多模态模型，最后给一张横向对比总表与选型决策框架。

> 一句话记住本章：**模型结构决定三件事——能处理多长的序列、花多少算力、适合什么模态与场景；工程优化都是在结构给定的边界内找最优解。**

## 02 架构选型坐标系：先建立四个轴

任何模型架构都可以用四个轴定位，后续每一节都回到这张坐标系：

| 轴 | 问题 | 关键量 |
|---|---|---|
| 时间/序列轴 | 能建模多长、多久以前的信息 | 隐状态/注意力窗口/状态维度 |
| 算力轴 | 每处理一个 token 花多少计算 | 序列长度复杂度、参数量 |
| 模态轴 | 输入是文本/音频/图像/视频/多模态 | 编码器结构、对齐方式 |
| 工程轴 | 训练/推理/部署成本与约束 | 显存、并行性、KV Cache、量化友好度 |

> 记忆锚点：**架构之争本质是“记忆机制与算力复杂度”之争——谁能在有限算力下记住更久、看得更远，谁就占优。**

## 03 循环网络：RNN / LSTM / GRU——曾经的时间建模主力

### 3.1 RNN：最朴素的时间记忆

RNN（循环神经网络）的核心是一个**随时间复用的隐状态**：每读一个新输入，就把“上一个隐状态 + 当前输入”一起算成“新的隐状态”，再输出。

~~~text
h(t) = f( W_hh·h(t-1) + W_xh·x(t) + b )
~~~

优点：参数量小、天然处理变长序列、每一步只依赖上一步状态（在线/流式友好）。
缺点：**串行**（第 t 步必须等第 t-1 步）、长程依赖弱（梯度消失/爆炸）、无法并行训练整段序列。

### 3.2 LSTM：给记忆装“阀门”

LSTM 在 RNN 基础上加了三条门控：

| 门 | 作用 |
|---|---|
| 遗忘门 | 决定丢掉多少旧记忆 |
| 输入门 | 决定写入多少新信息 |
| 输出门 | 决定放出多少记忆作为输出 |

并增加一条**细胞状态（cell state）通道**，让信息可以“直通”很远——这就是 LSTM 能记住更长依赖的原因。

### 3.3 GRU：把门精简到两个

GRU 把 LSTM 简化为“更新门 + 重置门”，参数更少、训练更快，效果在很多任务上与 LSTM 接近。适合中小规模时序任务。

### 3.4 对比与“淘汰原因”

| 模型 | 参数量 | 长程记忆 | 并行训练 | 工程现状 |
|---|---|---|---|---|
| RNN | 最小 | 弱 | 差 | 基本被替代 |
| LSTM | 中 | 中强 | 差 | 特定流式/轻量场景仍用 |
| GRU | 中 | 中 | 差 | 同上 |

**被 Transformer 取代的核心原因不是“不能记住”，而是“不能并行”**：GPU 时代，训练吞吐决定一切，串行结构的利用率天花板太低；同时超长依赖仍受梯度与容量限制。

> 工程落点：RNN 族并未死绝——**低算力设备、在线流式预测、轻量时序基线**里，LSTM/GRU 仍是高性价比选择；但文本大模型主线已全面转向可并行架构。

## 04 Transformer：全网最细拆解（当前 LLM 的事实底座）

### 4.1 从“词向量”到“上下文表示”

1. **Tokenization**：文本切成 token（第 03 章讲过）；
2. **Embedding**：每个 token 查表得到向量；
3. **位置编码**：因为注意力本身不分先后，必须注入位置信息（如 RoPE、ALiBi）；
4. **多层 Block**：每层 = 注意力 + 前馈网络（FFN/MLP）+ 残差 + LayerNorm/RMSNorm；
5. **输出层**：预测下一个 token 的概率分布。

### 4.2 自注意力：每个 token 都要“看全上下文”

对序列里每个 token，用三个矩阵算出 Query、Key、Value：

- Q 表示“我在找什么”；
- K 表示“我携带什么信息”；
- V 表示“我真正的内容”。

注意力分数 ≈ Q 与所有 K 的相似度，softmax 后加权求和所有 V——于是每个位置的表示都融合了全序列信息。

### 4.3 多头注意力：多个“视角”并行看

单头注意力只能学一种关系模式；多头把 Q/K/V 切成多份，各自学习不同关系（语法、指代、事实、位置），最后拼接。**头数越多表达越丰富，但计算与显存也越高。**

### 4.4 位置编码：给“无序”的注意力补上顺序

| 方案 | 思路 | 特点 |
|---|---|---|
| 绝对位置 | 给每个位置加一个向量 | 简单，外推差 |
| RoPE | 用旋转矩阵把相对位置编进 Q/K | 主流，相对位置友好 |
| ALiBi | 按距离给注意力分数加线性偏置 | 外推简单，长文本常用 |

> 位置编码直接决定“超出训练长度还能不能用”——这就是第 33 章上下文窗口拓展的架构根源。

### 4.5 Encoder-Decoder vs Decoder-only

| 结构 | 用途 | 代表形态 |
|---|---|---|
| Encoder-only | 理解/分类/检索 | BERT 类 |
| Encoder-Decoder | 翻译/摘要等条件生成 | T5 类 |
| Decoder-only | 自回归生成（当前主流） | GPT/Qwen/Llama 类 |

Decoder-only 成为主流的原因：统一了训练与推理目标（都是预测下一个 token），扩展性最好。

### 4.6 训练与推理特性（工程必读）

| 阶段 | 特性 | 工程影响 |
|---|---|---|
| 训练 | 全序列并行、可大规模 GPU 并行 | 适合超大集群（第 12 章） |
| Prefill | 一次性处理整段 prompt，计算密集 | 首字时延大头（第 34/39 章） |
| Decode | 每步只生成 1 token，需缓存历史 KV | KV Cache/连续批处理（第 28/33 章） |
| 复杂度 | 注意力 O(n²)（n=序列长度） | 长文本成本爆炸（第 33/36 章） |

### 4.7 工业级优劣小结

- 优点：并行训练、长程建模强、扩展性好、生态最成熟；
- 缺点：二次复杂度、KV Cache 显存、长上下文成本高、推理带宽瓶颈。

> 工程落点：主线 46 章的 KV Cache、量化、投机解码、PD 分离等优化，本质上都是在给 Transformer 的“贵”做对冲。

## 05 Mamba / 结构化状态空间模型：线性复杂度的新叙事

### 5.1 状态空间模型（SSM）直觉

状态空间模型用“状态”描述系统：当前输出由“当前输入 + 隐藏状态”决定，隐藏状态随时间更新。类比：一个带记忆的微分方程，每来一个输入，系统状态演进一次。

Mamba 属于**结构化状态空间模型（S4/S6 一系）**：把 SSM 参数化并做离散化，让它可以像 RNN 一样用固定状态递推，又能在训练时用卷积/扫描实现并行。

### 5.2 选择机制：Mamba 的关键升级

传统 SSM 对所有 token 用同一组转移参数；Mamba 让参数**依赖当前输入**（类似“注意力”的按内容选择）——需要记住的才记住、该忽略的忽略，从而在长序列上既高效又灵活。

### 5.3 复杂度对比

| 架构 | 序列建模复杂度 | 推理状态 |
|---|---|---|
| Transformer | O(n²) 注意力 | KV Cache 随长度增长 |
| Mamba/SSM | O(n) | 固定大小状态，不随历史增长 |

### 5.4 与 Transformer 的差异与适用

| 维度 | Transformer | Mamba |
|---|---|---|
| 长序列 | 贵但上限高 | 便宜、可极长 |
| 并行训练 | 成熟 | 扫描并行，生态仍在发展 |
| 硬件 kernel | cuBLAS/flash-attn 等成熟 | 需要专门 kernel（selective scan） |
| 生态/工具链 | 最成熟 | 相对新 |
| 适合 | 通用大模型、复杂推理 | 超长序列、流式、低成本场景 |

> 工程落点：Mamba 类模型（及 Mamba-Transformer 混合架构）在超长上下文、无限流式对话上有吸引力；但选型前要确认框架支持、kernel 效率与量化工具链——这正是主线“先选架构、再谈部署”的典型例子。

## 06 MoE 混合专家：大模型扩容的“稀疏杠杆”

### 6.1 从稠密到稀疏

普通 Transformer 每个 token 要经过全部 FFN 参数，叫**稠密激活**。MoE 把 FFN 换成一组“专家”，每个 token 只激活其中少数几个——**参数量变大，但每个 token 的算力基本不变**。

### 6.2 门控与路由

- 门控网络（Router）给每个 token 算“去哪个专家”的分数；
- 取 Top-k（常用 Top-2）专家做计算；
- 输出 = 被选专家的加权和。

### 6.3 负载均衡：MoE 训练的命门

如果所有 token 都涌向同一两个专家，其余专家“饿死”——所以训练损失里要加**负载均衡损失**，让 token 尽量均匀分布到各专家。

### 6.4 为什么 MoE 能“以小博大”

- 总参数量大 → 知识容量大；
- 每次激活参数少 → 推理算力低于同参数量稠密模型；
- 因此同算力下可以做得更大（如 Mixtral、DeepSeek-V3 等开源 MoE 系列，以官方发布口径为准）。

### 6.5 MoE 的工程痛点

| 环节 | 痛点 |
|---|---|
| 训练 | 专家间 all2all 通信、负载均衡、路由崩溃（所有人涌向一个专家） |
| 显存 | 全部专家权重都要驻留显存（即使单 token 只激活部分） |
| 推理 | 专家并行（EP）、路由局部性差、batch 内专家负载不均 |
| 量化 | 不同专家敏感度不同，简单统一量化易掉点 |

> 工程落点：MoE 的收益要在“算力成本”上算，而不是“参数量”上算；部署上需要 EP/TP 组合与专门的负载调度（主线第 39 章并行策略对 MoE 单独强调过）。

## 07 稀疏注意力体系：长文本的“省”字诀

### 7.1 为什么需要稀疏注意力

标准注意力每个位置要看全序列，n 个 token 就是 n² 次交互。长度翻倍，成本翻四倍——长文本必须想办法“少看”。

### 7.2 常见稀疏模式

| 模式 | 思路 | 代表 |
|---|---|---|
| 局部/滑动窗口 | 只看附近 w 个 token | 窗口注意力 |
| 跨步/空洞 | 隔几步看一个 | 稀疏 Transformer 类 |
| 全局 token | 少数“锚点”看全序列 | 全局+局部混合 |
| 分块 | 块内全看、块间稀疏 | Longformer 类思想 |

> 稀疏注意力是“结构上省”，需要硬件 kernel 配合才有真实收益。

### 7.3 FlashAttention：不改结构、省显存省带宽

FlashAttention 不是稀疏化，而是**IO 感知的精确注意力**：

- 把 Q/K/V 分块，在 SRAM（片上高速内存）里分块计算；
- 用在线 softmax 技巧，不写完整 n×n 注意力矩阵到显存；
- 结果：显存从 O(n²) 降到 O(n)，速度也显著提升，且**数值等价**。

### 7.4 工程影响

- 长文本推理/训练的显存大头之一就是注意力中间矩阵——FlashAttention 类 kernel 是第 36 章“融合注意力”的主力；
- 稀疏注意力 + FlashAttention 可叠加：结构稀疏省计算，IO 优化省带宽/显存；
- 实际收益必须看 kernel 支持与任务（不是所有稀疏都无损，长程依赖任务要谨慎）。

> 工程落点：主线第 33 章 KV Cache、第 36 章 FlashAttention 融合，与本节是同一件事的两层——**结构层决定“要不要看”，kernel 层决定“看得快不快、省不省”。**

## 08 世界模型 World Model：从“接龙”到“预测世界”

### 8.1 核心思想

语言模型预测“下一个 token”，世界模型预测“下一步世界状态”：给定当前观测与动作，预测未来的状态/观测。它把“学习”从文本扩展到**环境动态**。

### 8.2 关键概念

| 概念 | 说明 |
|---|---|
| 世界表征学习 | 把高维观测压缩成可推演的隐状态 |
| 时序推演 | 在隐空间滚动预测多步未来 |
| 预测式建模 | 用预测误差作为学习信号（类似自监督） |
| 规划 | 在想象出来的未来里选最优动作序列 |

### 8.3 与 LLM 的关系

- 语言本身也是一种“世界压缩”：LLM 记住的常识可以看成世界模型的文本投影；
- 多模态世界模型把文本、图像、视频、动作统一进预测框架；
- 具身智能/自动驾驶/游戏/机器人是主要落地方向（具体工作以官方发布为准）。

### 8.4 落地进展与工程视角

| 领域 | 进展形态 | 工程关注点 |
|---|---|---|
| 游戏 | 可交互视频生成/可玩世界 | 视频 token 化、长时一致性 |
| 自动驾驶 | 场景预测与规划 | 实时性、安全、闭环评测 |
| 机器人 | 视觉-动作预测 | 数据采集、 sim-to-real |

> 工程落点：世界模型目前仍偏研究与早期落地，评估时要区分“视频像不像”和“预测准不准”；对多数团队，先把它当作 LLM/多模态能力的一种扩展方向即可。

## 09 音频模型架构：从波形到语音大模型

### 9.1 音频的两种输入形态

| 形态 | 说明 | 常用架构 |
|---|---|---|
| 波形 | 原始采样点，1D 序列 | Conv-TasNet、WaveNet 类 |
| 频谱/特征 | 短时傅里叶/梅尔谱，2D“图像” | UNet、AudioTransformer |

### 9.2 Conv-TasNet：时域语音分离的经典

- 输入波形先经编码器变特征；
- 用**时间卷积网络（TCN）**堆叠建模时序；
- 生成掩码（mask）把混合信号“分开”。

优点：端到端、低延迟；常用于说话人分离/降噪。局限：对长程语义理解弱，属于“信号级”模型。

### 9.3 UNet 音频：把频谱当图像

UNet 的编码-解码 + 跳跃连接结构非常适合“谱图到谱图”任务（降噪、修复、声音合成）。它借用了图像分割的思路，把时间-频率看成二维空间。

### 9.4 AudioTransformer（AST 类）

把音频切成 patch/帧并做位置编码，像 ViT 一样送进 Transformer——能做音频事件分类、场景识别等“语义级”任务。代价是计算量与 Transformer 一致。

### 9.5 语音大模型的结构选择

| 任务 | 常用链路 |
|---|---|
| ASR | 音频编码器（Conformer 类）→ CTC/Attention |
| TTS | 文本 → 声学/离散 token → 声码器（主线第 27–33 章） |
| 语音 LLM | 音频编码器 → 投影 → LLM 联合建模（SpeechLLM 类，以官方发布为准） |
| 声音克隆 | 参考音频编码 + 生成模型 |

> 工程落点：音频建模的“分辨率”很贵——采样率越高序列越长；先用降采样/特征压缩再进 Transformer 是通用省钱手法。

## 10 图像与多模态模型：CNN、ViT、Swin 与图文对齐

### 10.1 CNN：图像的“先验派”

卷积神经网络假设“邻近像素相关、位置平移不变”，用卷积核滑动提取局部特征。优点：参数高效、数据效率高、适合中低算力；缺点：感受野有限，需要很深才能看到全局。

### 10.2 ViT：把图像切成 patch 的 Transformer

ViT 把图像切成固定 patch（如 16×16），每个 patch 展平后当“token”送进 Transformer。优点：全局建模、可扩展到大规模；缺点：需要更多数据/更大算力，归纳偏置弱。

### 10.3 Swin Transformer：层级化 + 窗口注意力

Swin 引入**层级特征图**（像 CNN 一样逐层缩小）和**移动窗口注意力**：窗口内算注意力（省算力），窗口间通过移动实现信息交互。兼顾 ViT 的表达与 CNN 的效率，是视觉主干的重要代表。

### 10.4 多模态对齐：图文怎么“对上”

| 结构 | 思路 |
|---|---|
| 双塔（对比） | 图像编码器与文本编码器各自输出向量，拉近配对样本（CLIP 类） |
| 融合编码器 | 图文 token 一起进 Transformer（跨模态注意力） |
| LLM+视觉 | 视觉编码器 → projector → LLM，LLM 读“图像 token” |

### 10.5 LLM+多模态的工程注意

- **模态编码差异**：图像是 patch、音频是帧、视频是帧序列——统一成“token”后长度可能爆炸；
- **对齐质量**：projector/训练数据决定“看懂了没有”；
- **推理成本**：长视频/高分辨率输入的 token 数会迅速吃掉上下文窗口与显存；
- **评测**：不能只用文本基准，要有图文/音画跨模态评测（第 20 章体系扩展）。

> 工程落点：多模态的瓶颈往往不在“模型结构”而在“token 预算”：输入压缩、帧采样、分辨率分级是落地必做的工程动作。

## 12 落地选型决策树与主线映射

### 12.1 四步选型

1. **先定模态**：文本→主流 LLM；图像→CNN/ViT/Swin+LLM；音频→编码器+LLM；具身/预测→世界模型方向；
2. **再定序列长度**：超长/无限流式→Mamba/稀疏注意力/状态压缩；常规→Transformer；
3. **再定算力预算**：预算紧→小稠密/LoRA；要容量→MoE/大模型+蒸馏；
4. **最后查工程成熟度**：框架支持、kernel、量化、生态——结构再好，工程不成熟也别先上生产。

## 14 本章核心总结（TOP3）

**TOP1**：架构决定“序列能力×算力成本×模态边界”的三角：RNN 败于串行，Transformer 胜在并行与扩展但注意力 O(n²)，Mamba 用线性复杂度挑战长序列，MoE 用稀疏激活撬动更大容量。

**TOP2**：长文本工程的本质是给注意力的“贵”做对冲：KV Cache/量化/FlashAttention/稀疏注意力/PD 分离，全部服务于“少存、少算、少搬”。

**TOP3**：多模态与音频模型的关键不是“结构多炫”，而是“token 预算”：输入压缩、帧采样、分辨率分级与模态对齐数据，决定落地成败。
