# 全局强制代码落地规范（code/ 全目录统一遵守）

> 适用范围：llm-fullstack-handbook/code/ 下**每一个** .py 文件。
> 目标人群适配：新手跑通（L1）/ 工程师落地（L2）/ 资深优化（L3），三层缺一不可。

## 一、代码层级规范（三层结构必带）

| 层级 | 命名/标记 | 受众 | 硬性要求 |
|---|---|---|---|
| 第一层 极简 Demo | 文件名含 demo 或 docstring 标 【层级】L1 | 新手入门 | 依赖最少、逻辑最短、零基础 100% 本地跑通 |
| 第二层 工程标准 | 文件名含 engine 或标 【层级】L2 | 工程师落地 | 参数配置、异常捕获、日志输出、参数校验、断点/设备兼容 |
| 第三层 高阶优化 | 文件名含 opt 或标 【层级】L3 | 资深优化 | 落地本章核心优化点（提速/省显存/提吞吐/防过拟合/稳收敛/降延时） |

- 每个主题目录（00_rnn_lstm_gru ... minimind_style）内必须同时存在 L1/L2/L3，
  允许一个文件内含多个层级函数，但必须在 docstring 中声明包含哪些层级。
- 自动化检查：`python code/scripts/check_code_standard.py`。

## 二、代码配套文档强制字段（每条代码必带，禁止裸代码）

每个 .py 文件的模块 docstring 必须包含以下字段（自动化检查按关键词匹配）：

1. 【层级】—— 本文件属于 L1/L2/L3（或声明多层级结构）
2. 【环境依赖】—— Python 版本、关键库精确版本（pip install xxx==版本）、CUDA 适配说明
3. 【核心逻辑】—— 关键逻辑/核心公式/关键步骤（配合正文逐行注释，通用语法不重复注释）
4. 【关键参数】—— 每个超参/阈值/开关：默认值 + 最优值 + 适配场景
5. 【避坑】—— 本文件 Top 高频坑（含与【高频报错】的互相引用）
6. 【运行结果示例】—— 真实输出样例（命令 + 输出片段 + 成功标识 + 指标）
7. 【高频报错 Top5】—— 报错现象/原因/一键修复（代码或配置）
8. 【输出解读】—— 如何看日志/指标判断是否成功
9. 【工程改造方向】—— 如何换自己数据集/接入自己项目/迭代优化

## 三、章节差异化代码落地标准

### （1）预训练 / 数据工程章节
重点产出：采集、清洗、去重、过滤、脱敏、质量打分、数据集构建、增量预训练启动、
断点续训工具；必须解决：污染、重复、脏数据、格式不统一、中断无法续训。
### （2）微调 / 对齐章节
重点产出：SFT 数据预处理、模板封装、LoRA/全量微调、蒸馏、奖励模型、PPO、
过拟合检测修复、微调效果评估；必须解决：不收敛、过拟合、loss 震荡、对话差、对齐不精准。
### （3）部署推理基础章节
重点产出：vLLM/SGLang 一键部署、TensorRT 固化、INT4/INT8 量化、KV Cache、
流式封装、高并发封装、负载均衡 Demo；必须解决：推理慢、显存爆炸、吞吐低、流式卡顿。
### （4）推理编译器高阶优化章节
重点产出：图优化、算子融合、CUDA Graph、PagedAttention 原理复刻、编译产物验证、
性能回归基准；必须解决：kernel 选型错误、图捕获失败、量化掉点、基准不可复现。
（本仓库 code/ 目前以第 00 章架构原理 Demo 为主，落地以上标准时按就近原则映射章节重点。）

## 四、代码质量验收标准（全部满足才算合格）

- [ ] 每个 .py 都有【层级】与 9 个文档字段（见上），check_code_standard.py 通过
- [ ] 每个主题目录含 L1/L2/L3 三层代码
- [ ] 代码可运行：python xxx.py 有真实输出；训练类有 loss/acc 指标下降证据
- [ ] py_compile 全部通过
- [ ] 文档中的“运行结果示例”来自真实运行，禁止编造
- [ ] 每个文件含本章高频报错 Top5 与一键修复方案
- [ ] 不虚构版本/工具能力，涉及库版本以官方文档为准
